## 2. 수련 템포 계산

목표(확정): **초식당 대성까지 수 시간 수준.**

### 2-1. 계산식

```
대성 소요 시간(초) = 대성 목표(10,000) ÷ (수련 중인 초식의 초당 정상 발동 수 × 수련 배율)
```

자동 순환 구조에서는 해금된 초식을 차례로 돌기 때문에, 해금 초식 수가 n개이면 수련 중인 초식은 대략 n번에 한 번 발동한다.

```
수련 중인 초식의 발동 간격 ≈ max(자동 초식 발동 간격 × n, 해당 초식 재사용 대기시간)
```

### 2-2. 예시 계산 [가안]

가정: 자동 초식 발동 간격 1.0초, 초식 재사용 대기시간이 발동 간격보다 짧음, 수동 발동 없음, 항상 대상이 있음.

| 해금 초식 수 (n) | 수련 중 초식 발동 간격 | 주력(×1.0) 대성 시간 | 보조(×0.5) 대성 시간 |
|---|---|---|---|
| 1 | 1.0초 | 약 2.8시간 | 약 5.6시간 |
| 2 | 2.0초 | 약 5.6시간 | 약 11.1시간 |
| 3 | 3.0초 | 약 8.3시간 | 약 16.7시간 |
| 4 | 4.0초 | 약 11.1시간 | 약 22.2시간 |

- 오프라인 시간은 효율 50%가 곱해지므로 같은 시간 대비 절반만 진행된다.
- 수동 발동(정상 발동)이 추가되면 실제 시간은 더 짧아진다.

**관찰**: 순환 방식에서는 뒤 초식일수록 대성 시간이 n배로 늘어난다. 1초식은 약 3시간이지만 4초식은 11시간을 넘어 "수 시간"을 벗어날 수 있다. 이 문제는 [미확정] O-03에서 결정이 필요하다. 후보는 다음과 같다(결정하지 않음).

| 후보 | 장점 | 단점 | 개발 난이도 |
|---|---|---|---|
| 그대로 둠 (뒤 초식이 자연스럽게 오래 걸림) | 규칙이 단순, 깊은 수련의 무게감 | 후반 초식 템포가 "수 시간"을 벗어남 | 없음 |
| 수련 중인 초식에 순환 가중치 부여 | 템포 일정 | 순환 규칙이 복잡해짐 | 낮음 |
| 대성한 초식은 수련 대상에서 제외하고 배율을 남은 초식에 몰아줌 | 템포 일정, 규칙이 직관적 | 수련 배율 개념이 늘어남 | 낮음 |
| 초식별 대성 목표를 다르게 둠 | 데이터만으로 조정 | "초식당 10,000회" 원칙과 충돌 | 낮음 (단, 원칙 변경 필요) |

## 7. 수집·소환 수치

- 비급 조각 필요 개수, 천장 수치, 소환 확률, 소환 천장, 조각 전환 개수는 **모두 미정**이다(O-15, O-29). 이 문서에서 임의 값을 정하지 않는다. 구현 시에는 데이터 파일에 자리만 만들어 두고 테스트용 값을 넣는다.

## 8. 밸런스 조정 방법

1. 모든 수치는 JSON 데이터에 둔다.
2. 디버그 빌드에 시간 배속, 수련 횟수 편집, 재화 지급 같은 테스트 도구를 넣는다.
3. 기준 지표: 첫 초식 대성까지 걸린 실제 시간, 스테이지당 소요 시간, 경지별 도달 시간, 재화 잔고 추이.
4. 지표를 보고 데이터만 수정해 다시 테스트한다.
